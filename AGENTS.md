# Working in this repository

EDUNEXUS is a learner attendance and academic records system for Balili Elementary School, La Trinidad, Benguet. It will hold real records for roughly 897 learners and 33 staff. Correctness and privacy are the point of the project, not a nice-to-have.

This file is the working contract for any agent or person picking the project up. It is deliberately tool-neutral: Codex reads `AGENTS.md` directly, and `CLAUDE.md` is a one-line pointer to this file, so there is one source of truth rather than two that drift.

## Start of session

1. Read **[docs/status.md](docs/status.md)** — where the last session stopped, what is in flight, and the single next action.
2. Read **[docs/constraints.md](docs/constraints.md)** — standing rules, blocking gates, settled decisions. Where any other document disagrees with it, this one wins and the other is wrong.
3. Check `git log --oneline -5` and `git status`. The history is the durable record; `docs/status.md` only summarizes it.

Then read as needed: [docs/roadmap.md](docs/roadmap.md) for sections and what each next step waits on, [docs/architecture.md](docs/architecture.md) for identity, the database boundary, concurrency and audit, [CHANGELOG.md](CHANGELOG.md) for every release mapped to its section and migration, [docs/school-information-requests.md](docs/school-information-requests.md) for what the school still owes us, and [docs/runbooks.md](docs/runbooks.md) for removing access, rolling back, restoring and responding to a leak. [docs/school-forms.md](docs/school-forms.md) records what the school's own SF2, SF4 and SF9 specify, and what must not be copied out of them; the forms themselves are not in this repository.

`docs/manuscript-analysis.md` explains where the requirements came from and which of them turned out to be contradictory. The manuscript itself is **not** in this repository and must never be committed.

## End of session

Before you stop, leave the project pickup-ready for a different agent:

- **Commit finished work.** An increment is one commit. Never leave a half-finished module uncommitted without saying so in `docs/status.md`.
- **Update `docs/status.md`**: current version, last commit, what just shipped, the single next action, anything in flight, and any question waiting on the user. Keep it short — it is a pointer, not a second changelog.
- **Record decisions** in the settled-decisions table in `docs/constraints.md`, with the date. A decision that lives only in a chat transcript is lost the moment the tool changes.
- Leave the working tree clean, or explain in `docs/status.md` exactly what is dirty and why.

## Rules that do not bend

- **Never modify an applied migration.** They are checksummed and the runner refuses a changed file. To alter a deployed function, `create or replace` it in a **new** migration. Migrations `0018`, `0019` and `0021` each do this; follow that pattern.
- **Never invent DepEd policy.** No grading weights, transmutation table, rounding rule, passing mark or numeric Kindergarten grading. If a rule is not in `docs/constraints.md` as settled, it is not ours to choose. A wrong rule here silently corrupts real report cards.
- **Never weaken a backend control to make a frontend workflow easier.** The API is the authority; the UI is a convenience over it.
- **Never commit or print credentials** from `.env` or `.local/`. Scratch scripts that need them run from `.local/` and are deleted afterwards.
- **Synthetic data only** in tests, and roll back anything written to a hosted database.
- **Absence of a record is not evidence.** An unmarked attendance session and an unrecorded score are `null`, never zero and never "present". Several modules exist specifically to preserve this.
- **The SF10 is one cumulative record per learner, and it begins at Grade 1.** It is never a stored document: it is derived on every read, one scholastic block per school year, from the enrolments EDUNEXUS recorded and the previous years transcribed from the school’s own documents (0051), **one school year at a time**: a bulk importer for them was built on 2026-11-04 and reverted the same day, is not a go-live requirement, and must not be rebuilt without the school asking for one (see the roadmap). There is no per-year SF10 to create and none to carry forward. Kindergarten is never a block — it is the credential presented for Grade 1, on the form’s eligibility line — so a learner whose only year is Kinder has no SF10 and is refused one rather than given a blank; their records are the SF5-K and the ECCD checklist, which EDUNEXUS neither holds nor replaces (decided 2026-11-04).
- **Teachers read only the learners in the classes they advise. Changing a learner record is a manager's — with two exceptions.** The rule came from an explicit decision where the manuscript contradicted itself; the exceptions were each asked for afterwards, and each is deliberately narrow. An adviser may: encode the *historical* academic records of the learners currently in the sections they advise, at any previous grade level, because the documents being transcribed are their own class records (2026-11-03); **take an already-registered learner into a class they advise**, which only ever gives a class to an enrolment that has none (2026-11-05); and **take one back out again**, which returns that enrolment to having no class and never moves them elsewhere (2026-11-06). **Registering a new learner into their class was a third, and was withdrawn on 2026-11-07**: every learner an adviser brings in now goes to the office for approval as a one-row class list, and `0063` withdrew the grant on `register_learner_into_section` rather than dropping it. That was also an adviser's only way to record a guardian, which is therefore a manager's field now.
  Everything else stays a manager's, and the list matters: a teacher cannot move a learner out of another adviser's class, withdraw or re-enter one, correct a profile, assign or correct an LRN, or change a grade. **The read scope never widened** — row security is untouched, so a teacher still sees only their own classes, and the one place they are shown learners outside them is the pullable list, which writes a `record_access_events` row naming every learner it disclosed. Both writes go through `place_enrollment` and `move_enrollment`, the same writers everything else enrols through (`may_advise_section` is the single predicate), and every such write is journalled under the teacher's own name.
  **No subject-teacher access exists, and none is to be integrated.** The role is unconfirmed by the school and its integration was deferred on 2026-11-05: confirm the role before asking what it may do, and do not stretch the adviser pull to cover it — it is scoped to a section the teacher advises, and a subject teacher advises none (the gate is in `docs/constraints.md`).
- **Automatic enrolment into next year is for a promotion only (`0071`, 2026-11-09).** An approved `promoted` or `conditionally_promoted` outcome enrols the learner at the next grade with no section; `retained` and `remedial` enrol nobody. Both conditions the school named are structural rather than re-checked: `advance_approved_enrollment` reads `promotion_decisions`, which only the adviser’s recommendation writes and only a manager’s approval sets to `approved`. **Do not widen this back to retention** without the school asking — it was narrowed deliberately, the day it was built. **Next year’s classes still carries a retention**, and that asymmetry is the point: it is a reviewed preview a manager commits, not a side effect.
- **A term accepts grades only once it has started, and promotion is closed until a class’s report cards are complete.** Both are 2026-11-09 decisions, both enforced in the database (migration `0069`), and both are the kind of gate a later session "fixes" by removing it when a fixture is inconvenient. The term window is a trigger on `report_grades`, `report_values` and `report_notes` -- on the tables, not in the four writers, so none can forget it -- and a term already begun never closes, because the ECR’s figures arrive after a term is over. The promotion gate counts **what that grade’s card prints**: Kindergarten waits for nothing, a descriptively graded grade waits for its narratives. **An approved outcome then enrols the learner into the following school year itself**, at the grade the outcome leads to and with **no section** (0049), or the moment that year is created if it does not exist yet. A test that cannot reach promotion should record the grades, as `tests/workflow-notifications.test.ts` now does; it is not evidence the gate is wrong. See [the promotion gate](docs/promotion-gate.md).

- **An SF9 belongs to an enrolment, and an issuance is never overwritten.** The card is derived on every read from `report_grades` and friends, all keyed by `enrollment_id`, so one learner’s Grade 1 and Grade 2 cards are different records and a promoted learner’s new card is blank by construction. `form_issuances` CHECKs that an `sf9` row names both an `academic_year_id` and an `enrollment_id`, and the prior a reissue looks for is keyed on that scope, so a later grade can neither find nor supersede an earlier one; the table is append-only. **This is a property of the key rather than a feature, which is exactly why it would break silently** -- an inner join in `read_sf9_source`, or a change to the issuance scope, would pass every test written before `tests/sf9-per-grade.test.ts`. Do not introduce a stored SF9 document. See [the SF9 history](docs/sf9-history.md).

- **Nothing computes a grade.** No total, average, percentage, MPS, GWA or transmutation of scores exists anywhere, including client-side in the UI. This is blocked deliberately, not an oversight. Grades on the forms are the ones advisers enter from the DepEd ECR (decided 2026-10-08).
- **Attendance figures come only from the school's recorded rule.** The SF2's and SF4's averages and percentages are computed in `src/modules/forms/attendance.ts` from the rule the principal records, and nowhere else; with no rule, or with an unmarked session, an unset date or an alternative-delivery date, the figure is empty, never estimated. A day of classes still to come is none of these: while a month has one, the SF2 counts to date and says so (`to_date`), and is issued only once the month is over. Attendance on the SF9 is counted from the register too, and is never typed. Every SF4 figure is counted **by section**, so a learner registered at a grade with no class yet is on no row and in no total: the count is reported on its own, never folded into a rollup (a grade subtotal must equal the rows printed above it), and the SF4 is refused until every registered learner is in a class (0052).

## The increment pattern

Work lands as one reviewable increment per commit. Every module in `src/modules/` follows the same shape, and a new one should too.

1. **Check the gate.** If the work sits behind a closed gate in `docs/constraints.md`, stop and say which one. Do not approximate a missing school decision with a default.
2. **Migration** in `database/migrations/NNNN_name.sql`, with its checksum added to `database/migration-checksums.json` (`tests/migrations.test.ts` says what to add): tables, partial unique indexes, RLS policies, `grant select` only to `edunexus_app`, `version_record` and `audit_record` triggers, then `security definer` writer functions that are revoked from `public` and granted narrowly.
3. **Module** in `src/modules/<name>/` with `contracts.ts` (Zod schemas, operation list, response schemas) and `service.ts` (thin; the database function does the validating).
4. **Wire it**: `src/operations.ts`, the dispatch line and readiness check in `src/http-app.ts`, the response map and tag in `src/openapi.ts`, and any new error codes in `src/core/errors.ts`.
5. **Tests** in `tests/<name>.test.ts` — about ten focused cases, covering the happy path, every refusal, manager/teacher isolation in both HTTP and SQL, version conflicts, and a journal-failure rollback.
6. **Docs**: a section file in `docs/`, plus updates to `README.md`, `docs/roadmap.md`, `docs/architecture.md`, `docs/frontend-handoff.md` and `CHANGELOG.md`.
7. **Version** bump in `package.json`, `package-lock.json` and the `version` and `description` in `src/openapi.ts`, then `npm run api:export`.
8. **`npm run check`** must pass, then commit.

### Database conventions

- Writers acquire `pg_advisory_xact_lock(82412001)`, the shared academic-setup lock, then `select ... for share` on the school year row when year status matters.
- **The daily register is the one exception, because 27 advisers use it at once.** Since `0023` its reads take `82412001` shared plus their section's lock `(82412002, hashtext(section_id))` shared, and a confirmation takes `82412001` shared plus its section's lock exclusively. Take locks first, before any read, and always in that order: a transaction holding a lock shared must never then ask for it exclusively. `npm run test:race` and `npm run test:load` are the proof; run both after touching any of this.
- Every mutation takes the caller's last-read `version` and raises `P0003` on a mismatch. Never silently overwrite.
- Every mutation writes an immutable journal row in the same transaction, with before/after snapshots, actor, reason and request ID. If the journal cannot be written, the whole change rolls back — there is a test for this in every module.
- A reason is 10–500 single-line characters. Reuse `subjectReason` from `src/modules/subjects/contracts.ts`.
- Security-definer functions bypass RLS, so any row policy they need must be re-checked inside the function. `edunexus.assert_may_grant_role` exists because of exactly this.
- Use an identity column, not a random uuid, for any journal paged newest-first. A uuid cursor is not chronological, and the resulting bug only shows up under a full test run.
- Do not shadow a column name with a PL/pgSQL variable. A local named `value` inside `for ... in select value from jsonb_array_elements(...)` is ambiguous and fails at runtime, not at creation.

### Error code ranges

`P0002` not found and `P0003` version conflict are shared. Module ranges: `P01xx` timeline, `P02xx` identity, `P03xx` enrollment records, `P04xx` placement, `P05xx` calendar, `P06xx` attendance, `P07xx` months, `P08xx` monitor, `P09xx` follow-ups, `P10xx` subjects, `P11xx` offerings, `P12xx` policy drafts, `P13xx` adoptions, `P14xx` bindings, `P15xx` invitations, `P16xx` assessment tasks and scores, `P17xx` roster submissions, `P18xx` school forms, `P19xx` report-card records, `P20xx` end-of-year outcomes, `P21xx` next year's classes, `P22xx` the public site, `P23xx` the front page's questions, `P24xx` staff profiles, `P25xx` historical academic records, `P26xx` an adviser’s own class roster, `P27xx` notifications. **Next free range: `P28xx`.**

### Supabase configuration

`supabase/config.toml` mirrors the live auth configuration, pulled with `supabase config pull`. It exists so `supabase config diff` can catch drift, and it is how the redirect allowlist, MFA settings and password rules were verified.

**Never run `supabase config push`.** The pull deliberately skipped settings it could not represent, so a push would write local defaults over them, including disabling Twilio. The Email provider toggle is not in this schema at all: it lives in the dashboard, or in the Management API, which needs an account-level token rather than the project API keys kept in `.local/`.

### Frontend

The workspace is a Vite + React + TypeScript app in `web/`, built into `public/` and served by the API at `/app`. The school's public front page is a second entry, `web/site.html` with `web/site/` and `web/styles/site.css`, served at `/` and reading `GET /api/v1/public/site`, the one route that needs no token; it shows only what managers publish on **Public site**, and never a learner. Its one image is the hero illustration in `web/public/images/`, served from this origin and versioned in its file name; it shows no person. `web/api.ts` throws an `ApiError` carrying the server's own `code`, so screens react to specific codes rather than message text. `web/components/primitives.tsx` holds the shared `Editor`, `FormSheet`, `Finder`, `Table`, `TableSkeleton`, `Task`, `Cell`, `Select`, `Badge`, `Callout`, `EmptyState`, `Unrecorded`, `Pager`, `Button`, `PrintButton`, `PageHeader`, `StatusLine`, `Spinner`, `FactsSkeleton`, `BlockSkeleton` and `localToday` (since 0.103.0 a `Table` read again keeps its rows on screen, dimmed and inert, until the fresh ones arrive, so never unmount a list to show it is loading, and every box follows the rule at the head of the card styles in `app.css`); `web/dates.ts` holds plain-calendar-date arithmetic, which never converts a `YYYY-MM-DD` through local time; `web/components/overlay.tsx` holds `Sheet` (with `full` for a document such as an SF9, which takes the working area beside the rail and follows it) and `Confirm`, and only the innermost open overlay answers the keyboard; `web/screens/CardEditor.tsx` holds the report card's shared draft (`useCardDraft`), box list (`cardBoxes`) and review (`CardReview`), used by Promotion → Report card and by typing on the SF9 itself; `web/components/palette.tsx` holds the Ctrl+K command palette; `web/components/figures.tsx` holds `StatTile`, `Donut` and `Timeline`; `web/components/icons.tsx` holds the inline icon set and `web/components/avatar.tsx` holds `Avatar` and `PictureCanvas`, which draw a staff photo on a canvas from bytes read through the API (so a photo, too, loads no image), and `web/photo.ts` frames and re-encodes one in the browser; `web/components/brand.tsx` the EDUNEXUS mark, a vector redraw of the supplied artwork in `docs/brand/` because the content policy loads no image file; `web/components/AppShell.tsx` holds the rail, top bar and profile menu; `web/styles/tokens.css` holds the design tokens; `web/learning-areas.ts` holds the learning areas the school's report cards print, a proposal a manager reviews and never a seed; `web/deped.ts` holds what DepEd's own 2026 orders state, each with its source, offered the same way; `web/components/batch.tsx` holds `BatchSheet`, the reviewed one-request-per-row batch every setup sheet uses; `web/calendar-fill.ts` holds the pure rules for filling a calendar range; `web/csv.ts` holds the formula-defusing CSV writer, the class-list and register files, and the class-list **template** — generated from `ROSTER_HEADER`, its one copy of the columns `GET /roster-imports/template` publishes, which `tests/registry-address.test.ts` asserts are equal (a copy rather than a fetch, because that endpoint is manager-only and advisers prepare class lists too) and `web/components/filerules.tsx` holds `FileRules`, the columns-and-rules block both screens that take a class-list file show, which is given that header rather than keeping a second copy of it; `web/components/seeded.tsx` holds the seeded-data banner; `web/components/print.tsx` holds `PrintCopy`, which prints a sheet or card on a page of its own; `web/xlsx.ts` lays a workbook out on a grid that measures itself (rows fitted to wrapped text; `problems()` names anything cut off or shown as #####, and `allow()` tells Excel what a cell of a template may hold) and writes it with ExcelJS, loaded only when a file is saved; `web/components/affects.tsx` holds `Affects`, the one list of what else each kind of change reaches, shown above every save that feeds a form; `web/forms/details.tsx` edits the school heading and staff positions from a form; `web/help/` holds the in-app help (a guide per screen and role, the articles, and `Prose`, which renders `**Label**`, `*words*` and `{route}`; a test finds every `**Label**` in the screens' source, so renaming a control means updating its guide) and `web/screens/Help.tsx` its screen and the `HelpSheet` the shell opens over any page on the `?` key (since 0.82.1 the rail is the only visible way in: the top bar has no Help button) (`web/help/context.tsx` lets `StatusLine` link a refusal to its FAQ answer through the code `message()` remembers); `web/components/tour.tsx` runs the guided tours in `web/help/en/tours.ts`, which point at `data-tour` attributes and never press anything; `web/record-fields.ts` holds the learner and school fields the registry, School profile and the forms share (a learner's are the name, LRN, birth date, sex and one line of `address`, added 0053; **a further learner field is behind the learner-fields gate** and needs a decision, not a line here) and `web/forms/` holds the official form layouts (`sf2.tsx`, `sf4.tsx`, `sf9.tsx`, `sf10.tsx`), their shared month and issue controls, and the shapes the form endpoints answer with. Screens are declared in the route table in `web/routes.tsx` (a route's `hiddenFor` leaves it out of a role's navigation without touching what the API allows), take `{ api, me, manager, setStatus, reload, token, route }` and refetch on `token`. Adding a screen means adding a route and a component; a module with no screen yet renders an honest placeholder rather than disappearing from the navigation.

Five rules the workspace will not bend on, each replacing something that was wrong before:

- **A missing record is drawn, never blanked and never an em dash.** `Unrecorded` names what is absent. Absence of a record is not evidence, and the interface has to say so as plainly as the database does.
- **A field rejection belongs beside its field.** `Editor` maps `ApiError.fields[]` onto the controls and marks them, and **says each problem once**: with every rejected field in sight it draws no summary and focuses the first one, whose message `aria-describedby` reads; only a rejected field out of sight, or a server message that belongs to no field, gets a summary, which names the fields as jump links without repeating their messages (since 0.111.1). Only an error the server does not attribute to a field goes to the page's `StatusLine`.
- **Creating a record opens a `Sheet`**, never a second form parked under the list it adds to. The primary action lives in `PageHeader`'s `actions` slot.
- **Anything irreversible goes through `Confirm`**, never `window.confirm`, and says what it costs in the screen's own words.
- **A control that is waiting says so, in words.** The school reported "a delay when clicking", and the delay was not the fault — nothing said the system was working. A button that only goes `disabled` is drawn at .45 opacity under a `not-allowed` cursor, which is exactly how a switched-off button looks, so the next thing a person does is click it again. So: a button that acts turns its own label progressive ("Saving…", "Recording…", "Working…") **and** carries `aria-busy`, which is what stops the stylesheet drawing it as off; a button disabled because something else is running is *not* marked, because it is unavailable rather than working; and every request in the workspace is counted at one place, `onApiBusy` in `web/api.ts`, which the shell shows as **Working…** in the top bar after 300ms — for the many clicks that open a sheet or refetch a list and have no control of their own to speak through. `tests/web-buttons.test.ts` gates all of it, and a secondary button keeps a visible edge for the same reason: with none it reads as a line of text to anyone who does not already know the interface.

The command palette searches the route table and, since 0.68.0, the help and FAQ written about it, and nothing else; help is fixed text that names no record. Every learner and enrollment list writes a `record_access_events` row naming the records it returned, so a palette that searched the registry would write one per keystroke.

Since 0.81.0 there is a dark theme, chosen on My profile: it retunes the tokens under `@media screen`, and the paper forms (`.paper`) keep the light ones. So **a colour is always a token**, never a literal, outside `.paper`; a literal white or black is invisible in one theme or the other. Check a new screen with axe's contrast rules in both.

The rail has its own contrast-checked tokens — `--rail-ink`, `--rail-dim`, `--rail-faint` — so it can be retuned in one place; since 0.63.0 it is light, divided from the page by a hairline. Do not use the `--ink-*` scale inside it, or the rail scale outside it.

Since 0.106.0 the front page may frame this origin (`frame-src 'self'`) and the workspace may be framed by this origin only (`frame-ancestors 'self'`): **Staff portal** opens `/app?embed=signin` in a panel over the front page, so the sign-in code and the sign-in service stay in the workspace. Widen neither further without a decision in `docs/constraints.md`; `tests/staff-portal.test.ts` pins both.

The workspace content policy is `default-src 'none'`, which has two consequences worth knowing before writing a screen: **every image a screen loads is served from this origin**, which the single `img-src 'self'` directive exists for, and a `data:` URL in CSS is still dropped — use the `Select` primitive rather than a bare `<select>` with a background-image chevron; and **`style={{ … }}` does nothing** in the deployed app, because `style-src 'self'` covers inline attributes, so use a class. Both work under `npm run dev:web`, which is how they get missed.

Images are the exception to "the workspace loads no image file", and the exception is short and closed: `/favicon.svg`; the sign-in page's hillside and the front page's hero illustration from `web/public/images/`, neither showing a person; and the DepEd seal, DepEd wordmark and school seal in the SF9 and SF10 headings, added in the print pass of 2 November and versioned in their file names. A staff photo is still **not** one of these — it is drawn on a canvas from bytes read through the API (`web/components/avatar.tsx`), so no image file loads for it, and the brand mark in `web/components/brand.tsx` is still a vector redraw for the same reason. Anything new that would load an image needs a reason as specific as those.

Charts are hand-drawn SVG for the same reason: a library that rasterises to a canvas or injects a background image has nothing to draw into under this policy, and one that sizes a bar with `style={{ width }}` is dropped. SVG geometry attributes are not inline styles, so every data-dependent dimension is one of those.

**The Overview reads no learner or enrollment record.** Every list under `/learners` and `/enrollments` writes a `record_access_events` row naming the exact records returned, so counting the roster on each dashboard load would bury the privacy audit in its own noise. A learner count comes from `GET /enrollment-counts` (0.37.0), which answers with numbers by grade, names no record and writes no access row; never page a list to count it.

`tests/web-screens.test.ts` renders every route once. It catches a crash on first render, which a typecheck cannot, but effects do not run so it does not cover the data paths behind a fetch. `tests/web-shell.test.ts` renders the shell and asserts the two traps above are absent from the markup. Those files, and `tests/web-calendar.test.ts`, are excluded from the root `tsconfig.json` and listed in `tsconfig.web.json`; a new web test must be added to both or the server typecheck will fail on it.

**A screen's data paths are tested in a real DOM against the real API.** A file starting `// @vitest-environment happy-dom` mounts the screen with `tests/helpers/dom.ts`, whose `serverApi` is the workspace client pointed at an in-process API over PGlite, so fetches, reviews, confirmations and refusals run end to end; `tests/web-followups.test.ts` is the pattern. Because such a file imports both `web/` and `src/`, it is excluded from the root `tsconfig.json` and listed in `tsconfig.web-tests.json`, which adds Node types — not in `tsconfig.web.json`, whose missing Node types are what stop browser code reaching for `process` or `Buffer`. See [docs/frontend-handoff.md](docs/frontend-handoff.md) for every unbuilt screen and the rules it must respect.

The workspace prints: the `@media print` block in `app.css` drops the rail, top bar, filters and actions and keeps the register, because a section list is carried to a classroom on paper. New furniture goes in that block.

Sessions live in `sessionStorage` and die with the tab, **unless the person ticks "Keep me signed in on this computer" on the sign-in page**, which is the one sanctioned exception (decided 2026-11-03): one storage adapter in `web/api.ts` moves that session to `localStorage`, the choice is set *before* the sign-in call because the session is written as it returns, signing out forgets the choice so the next person at a staffroom machine starts with the box empty, and the box is pre-ticked only for someone who chose it on that computer before. Nothing else moves a session to `localStorage`. Saving a password is the browser's own password manager (decided 2026-10-28, D1a): `offerToSave` in `web/Account.tsx` tells it a password worked, and EDUNEXUS keeps nothing. The sign-in page shows the front page's hillside from `/images/`; it shows no person, and it is one entry on the closed list of images above, alongside the SF9 and SF10 seals. Interface preferences — the collapsed rail, the folded navigation groups — live there too, under `edunexus-ui-*` and wrapped in `try`/`catch`, because a private window throws on access and a shared staffroom machine should not keep one person's layout for the next.

### Style

Backend module and migration code is deliberately dense — multiple statements per line, minimal whitespace. Frontend code is conventionally formatted. Match the surrounding file rather than reformatting it. Comments are rare and explain *why*, not what.

## Commands

```bash
npm run check        # typecheck, tests, build. Must pass before commit.
npm run api:export   # regenerate docs/openapi.json after a contract change
npm run db:migrate   # apply pending migrations (needs the operator credential)
npm run dev          # local API on http://127.0.0.1:3001
npm run dev:web      # Vite dev server, proxying /api to 3001
npm run test:race    # opt-in: real two-connection lock races on a disposable Docker PostgreSQL
npm run test:load    # opt-in: 27 advisers submitting the register at once, on a disposable Docker PostgreSQL
npm run smoke        # after a deploy: health, the workspace and its assets, the version, and 401 on every operation
npm run demo         # local only: the real API and screens over synthetic records at http://127.0.0.1:5173/demo.html
npm run seed:test-data -- --rehearse   # the full seeded school against a throwaway database; SEED_CONFIRM=seed-production for the hosted one; --report-cards tops up an older seed; --fill fills every box the seed left empty
npm run reset:seeded-data              # the go-live wipe of a seeded hosted database: dry run unless RESET_CONFIRM=wipe-seeded-data
npm run drill:restore -- --confirm      # restore drill: live schemas streamed into a throwaway Docker PostgreSQL and proved; needs Docker; reads live only
```

Tests use PGlite and need no Docker or cloud credentials. The one exception is `tests/concurrency.pg.test.ts`, which skips unless `EDUNEXUS_RACE_PG_URL` is set; `npm run test:race` runs it against a throwaway container, and it must never be pointed at a shared or hosted server. The full suite takes about 90 seconds; run it in the background rather than blocking on it. A Claude Code session may see these commands rewritten by a local `rtk` proxy; that is a harness detail and changes nothing about what runs.

## When instructions conflict

Ask. `docs/constraints.md` exists because a briefing once described the state of the system in words that read like a prohibition, and the difference decided whether a whole module should be built. If a request and that file disagree, raise it in a sentence and wait — a wrong guess is expensive in a system that will hold real learner records.
